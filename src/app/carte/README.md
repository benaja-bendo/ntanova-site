# Composants de la carte publique

Une même carte sur l'accueil et `/carte/`, sans framework d'interface supplémentaire. La séparation suivie est celle des **données et règles, du rendu et de l'orchestration** ; pas de hiérarchie de classes ni d'abstraction générique.

| Modifier… | Point d'entrée |
| --- | --- |
| Structure HTML, tiroir/panneau, commandes et styles de carte | `src/ui/ExplorateurCarte.astro` |
| Contenu et actions de l'aperçu d'une école (disque du cycle, puces de niveau, deux blocs de preuve, trois boutons), popup et tiroir ; les icônes sont des tracés écrits dans ce fichier | `src/app/carte/apercu.ts` |
| L'école choisie sur la carte : grande épingle, halo, nom ; le nom du fond qui s'efface pour elle | `src/app/carte/choisie.ts` ; couches et zooms dans `src/modele/carte/couches.ts` |
| Quand charger, repli WebGL, connexion lente, lien plein écran | `src/app/carte/chargeur.ts` et règle pure `src/modele/carte/chargement.ts` |
| Initialiser MapLibre, ses couches et interactions | `src/app/carte/ilot.ts` |
| État de l'application : recherche, liste, sélection, URL, tiroir et position sur geste | `src/app/carte/interface.ts` |
| Format de vue et filtrage sans navigateur | `src/modele/carte/navigation.ts` |
| Ce que le téléphone change (partie visible quand le clavier est ouvert, mots de « Ma position ») | `src/modele/carte/mobile.ts` |
| Données publiques, preuves, cycles et états géographiques | `src/modele/carte/donnees.ts` ; ports publics dans `src/modele/ports.ts` |
| Couleurs, espacements, typographie communs | `src/ui/jetons.css` |

**La page `/carte/` (refonte du 05/11/2026)** : le filtre de niveau est une rangée de puces au-dessus de la carte (elles servent aussi de légende : la lettre et la couleur de l'épingle) ; la recherche est dans le panneau sur ordinateur et dans le tiroir sur téléphone ; le tiroir a trois hauteurs (`petit`, `moyen`, `grand`), une poignée qui est un bouton (`aria-expanded`) et qui se glisse ; une école choisie donne à la carte une marge égale à la hauteur de sa fiche. Les ombres des éléments flottants et le halo de sélection sont des jetons. La trame d'un « déploiement programmé » s'efface entre les zooms 11 et 12,5 ; l'état d'une zone se lit dans la légende et le panneau, jamais sur chaque quartier.

**Sur téléphone (essai du 05/11/2026 sur un iPhone)** : la page tient dans l'écran, sans défilement (`html` et `body` à `100dvh`, `overflow: hidden` : `base.css` donne `100vh` au corps, qui sur iPhone est la hauteur sans les barres du navigateur et faisait défiler la page sous l'en-tête). Le rail des puces défile au doigt (`touch-action: pan-x`, jamais `pointer-events: none` sur un conteneur qui défile). Le tiroir bas prend la hauteur de son contenu (poignée, recherche, texte d'aide, légende des zones sur une ligne : la liste attend derrière la poignée) ; l'interface mesure sa hauteur (`--tiroir-h`) et le bouton « Ma position » comme l'attribution d'OpenStreetMap, écrite et jamais repliée, se posent juste au-dessus. Toucher la recherche ouvre le tiroir en grand ; quand le clavier est ouvert (`visualViewport` rétréci de 120 px ou plus), la carte et le tiroir prennent exactement la partie visible de l'écran (`data-clavier`, `--vv-haut`, `--vv-hauteur`). Un fond de carte absent ouvre le tiroir à moitié : la liste est ce qui reste. « Ma position » dit toujours ce qui se passe (refusée, impossible, connexion non sécurisée, hors du Congo-Brazzaville) et le message s'efface seul. Pour voir le vrai fond sur un téléphone en local : le serveur de tuiles n'autorise que ntanova.com, essai.ntanova.com et `localhost:4321` ou `8787` ; une adresse du réseau local est refusée, donc « le fond de carte ne se charge pas ». Pour l'essai, `outils/fond-de-carte/servir.ts` sert l'archive depuis le Mac (CORS ouvert) et le build est pointé vers lui.

Le composant Astro est instancié **une fois par page** (identifiants des champs et de la carte). Il ne connaît ni Supabase ni MapLibre ; il produit le HTML utilisable sans le moteur. Les pages lui donnent leur instantané public et lancent le chargeur. Le chargeur importe le moteur après décision ; l'application complète est initialisée uniquement sur `/carte/`. L'aperçu pose le texte avec `textContent`, et ne conserve aucune position personnelle.

Les versions accueil et application partagent le moteur et le rendu d'aperçu. Modifier le contenu de l'aperçu dans `apercu.ts`, pas dans les deux contrôleurs. Les styles restent dans le composant Astro pour qu'un changement visuel soit commun, sauf les pièces réutilisables (disque de cycle, fiche, preuves, étiquettes, lignes de liste, légende, bouton rond) : elles sont dans `src/ui/carte-pieces.css`, incluse par `@import` (une seule feuille servie, aucune requête de plus) et montrée dans chacun de ses états par le catalogue `/dev/catalogue/`. Les jetons restent la source des valeurs de design. Si l'interface grandit, extraire une responsabilité de `interface.ts` avec ses tests (recherche ou historique, par exemple) au moment où cela simplifie un changement réel.

Vérifications : parcours accueil (réseau, visibilité, repli, gestes, lien plein écran), parcours application (recherche, cycles, URL, preuves, position), mise en page aux trois formats et tests des règles pures. `pnpm poids` contrôle les graphes des deux pages ; la mesure HTTP servie reste obligatoire avant fusion. Le composant ne représente pas un nouveau système de design : il réutilise celui du site.
